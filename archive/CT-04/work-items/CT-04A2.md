# CT-04A2 — Repository registry and project binding

**Status:** Source-grounded parent contract proposed for operator adoption  
**Parent:** `CT-04A — Trusted Git boundary and repository registration`  
**Depends on:** Accepted CT-04A1 runtime source at `7313e81a56c0188574c436322d7fedc16e08bb70`  
**Source bundle SHA-256:** `ee0090898b7cedb1ecd0438f607b1e8ed60f0ec28a99f58b688400f025a2aeea`  
**Risk:** Critical  
**Primary areas:** repository domain state, immutable inspection evidence, workspace ownership, migration, authorization, registration, reinspection, reaffirmation, retirement, project binding, journal correlation, notifier ordering, event projection

## 1. Objective

Turn CT-04A1's bounded observational result into authorized, durable, workspace-owned repository state without importing its process authority into domain, storage, HTTP contracts, or browser code.

CT-04A2 must establish:

- a durable repository identity and state machine;
- immutable full-record inspection evidence;
- explicit separation of core identity, environmental evidence, and risk evidence;
- Owner-only host-path registration;
- honest feature-unavailable behavior when Git/root configuration is absent;
- same-workspace project binding and explicit binding retirement;
- explicit identity-evidence reaffirmation that preserves repository ID and bindings;
- terminal handling for structural identity mismatch and stored-evidence integrity failure;
- repository retirement with complete binding and journal consequences;
- structural workspace/repository/binding correlation in the event journal;
- audit and event ordering consistent with CT-02 and CT-03;
- strict public contracts with no arbitrary command, argv, environment, worktree, branch, or remote fields;
- no repository-side mutation.

## 2. Governing statements

> A1 observes. A2 interprets, authorizes, persists, and publishes. A2 may never reproduce A1's child-process or filesystem authority.

> Repository registration is a durable grant to use one accepted observational boundary against one workspace-owned local repository identity. A path string is not identity and an observation is not authorization.

> Core identity, environmental evidence, and risk evidence are separate facts with separate transitions. No single hash or status is allowed to erase those distinctions.

> Every explicit inspection becomes immutable evidence. Only meaningful state or evidence changes become workspace events; unchanged verification remains queryable through inspection history without generating activity noise.

## 3. Source-grounded A1 facts

A2 must consume the accepted A1 API exactly through the package root:

```ts
createRepositoryInspector(options)
parseRecordedObservation(value)
compareRepositoryObservations(recorded, current)
```

The accepted API returns a branded `ParsedRepositoryObservation`, typed failures with `subject`, `operation`, and `retryability`, and comparison arrays for core, environmental, and risk-scan differences.

A2 must not:

- deep import A1 private modules;
- create a second process runner;
- construct Git commands or environment variables;
- assume `reserved-root-overlap` is reachable after coherent A1 configuration;
- assume A1's core fingerprint protects `riskScan`, device evidence, `canonicalGitDirectory`, or `observedAt`;
- treat `observation-raced` as proof that repository identity changed;
- assume hard daemon death bounds an A1 orphan process;
- treat A1's risk scan as later mutation authority.

## 5. Common vocabulary

### 5.1 Repository status

```text
active
unavailable
identity-evidence-changed
identity-mismatch
evidence-blocked
retired
```

- `active`: core identity and accepted environmental evidence match the latest successful inspection.
- `unavailable`: the repository could not be observed because its path or required metadata was unavailable.
- `identity-evidence-changed`: core identity matches, but environmental device evidence differs from the accepted baseline and requires Owner reaffirmation before later mutation.
- `identity-mismatch`: structural Git identity or inode evidence changed, or the path now names a rejected repository class. This is terminal in A2 except retirement.
- `evidence-blocked`: stored evidence is corrupt, unsupported, or not comparable under the active inspection policy. This is terminal in A2 except retirement or external restore/repair.
- `retired`: the registration and its active bindings are closed. History remains immutable.

### 5.2 Evidence layers

```text
Core identity
    canonical top level
    canonical Git directory
    canonical common Git directory
    object format
    top/common inode
    A1 core fingerprint

Environmental evidence
    top/common device

Risk evidence
    scan scope and pattern
    sorted observed risk signals

Full-record integrity
    exact serialized observation bytes
    SHA-256 of those exact stored bytes
    successful A1 parse on every read across the trust boundary
```

The full-record checksum detects accidental or unauthorized row corruption under the application's storage-integrity model. It is not represented as protection against an attacker who can rewrite both the database and the running daemon.

### 5.3 Inspection evidence

Every explicit inspection of an existing repository creates one append-only attempt record, whether it succeeds or fails. Registration stores the second of two matching successful inspections as its authoritative registration evidence.

A successful attempt stores exact serialized observation bytes, their checksum, projected version/fingerprint fields, comparison evidence when applicable, and audit attribution.

A failed attempt stores only the bounded A1 error classification and allowlisted evidence. It never stores raw stdout, stderr, environment, config values, or arbitrary system messages.

### 5.4 Environmental baseline

Each repository has one accepted environmental-evidence inspection. Initially this is the registration inspection. Owner reaffirmation may advance it to a newer successful inspection while preserving repository identity and bindings.

### 5.5 Project binding

One project may have at most one active repository binding. One active repository may serve multiple projects in the same workspace. A binding is retired explicitly; it is never physically deleted or silently replaced.

## 6. State-transition policy

| Current | Observation or command | Result |
|---|---|---|
| active | same core/environment/risk | active; append inspection; no status event |
| active | same core/environment, risk differs | active; append evidence; emit evidence-changed event |
| active | core same, environmental differs | identity-evidence-changed |
| active | core differs or repository class changed | identity-mismatch |
| active | path/metadata unavailable | unavailable |
| active | recorded evidence invalid/incompatible | evidence-blocked |
| unavailable | same core and accepted environment returns | active |
| unavailable | core same, environment differs | identity-evidence-changed |
| unavailable | core or class differs | identity-mismatch |
| identity-evidence-changed | current evidence again matches accepted baseline | active |
| identity-evidence-changed | Owner reaffirms a fresh core-matching observation | active with new environmental baseline |
| identity-evidence-changed | core differs | identity-mismatch |
| identity-mismatch | retire | retired |
| evidence-blocked | retire | retired |
| any non-retired | retire | retired |
| retired | any inspect/bind/reaffirm | rejected; never reactivated |

`observation-raced`, timeout, process failure, host configuration failure, and policy-configuration failure do not by themselves change repository state. They create bounded failure evidence and audit only.

Every permitted repository status transition increments `version` by exactly one. An unchanged inspection does not update the repository row.

## 7. A1 failure mapping

A2b must map exact A1 codes, not only broad subjects.

| A1 result | A2 consequence |
|---|---|
| `path-unavailable`, `repository-metadata-unreadable` | candidate `unavailable` transition |
| `symlink-rejected`, `ownership-refused`, `not-primary-repository`, `not-git-repository`, `unsupported-object-format`, `unsupported-repository-extension` | candidate `identity-mismatch` transition on an existing repository |
| `recorded-observation-invalid`, `unsupported-observation-version`, `inspection-policy-version-mismatch` | `evidence-blocked`; never compare |
| `observation-raced` | retryable failed attempt; no status mutation |
| `invalid-path` | reject caller request; no repository-state inference |
| `outside-allowed-root`, `reserved-root-overlap`, `invalid-root-policy`, `invalid-options` | feature/policy failure; no identity mutation |
| Git executable/version/platform/root-daemon failure | feature unavailable; no identity mutation |
| spawn/timeout/overflow/signal/malformed output | operational failure; no identity mutation absent positive replacement evidence |
| successful observation | parse stored baseline, compare, then apply state table |

## 8. Authorization

| Operation | Owner | Editor | Viewer |
|---|---:|---:|---:|
| Register host path | yes | no | no |
| List/read stored repository state/evidence summaries | yes | yes | yes |
| Explicit reinspection | yes | yes | no |
| Reaffirm environmental evidence | yes | no | no |
| Bind active repository to project | yes | yes | no |
| Retire one project binding | yes | yes | no |
| Retire repository | yes | no | no |

Authorization happens before A1 creation or inspection. A nonmember receives the existing indistinguishable missing-resource behavior. A known active member with insufficient role receives a bounded denial and, where policy requires, a workspace audit record without host inspection.

## 9. Feature configuration

The daemon remains useful for planning when repository inspection is not configured.

- If repository configuration is entirely absent, the daemon starts with the feature disabled.
- If the operator provides configuration but it is malformed or unsafe, startup fails rather than silently disabling it.
- A1 inspector creation is lazy and memoized for authorized repository operations.
- List/read, retirement, and binding retirement can operate from stored state while inspection is unavailable.
- Registration, reinspection, reaffirmation, and new binding fail with an actionable feature-unavailable response when A1 cannot be created.
- No fallback to ambient `PATH`, current directory, global Git config, or implicit roots is permitted.

## 10. Journal vocabulary

The parent A2 target includes these audit actions:

```text
repository.register
repository.inspect
repository.reaffirm
repository.retire
repository.bind-project
repository.unbind-project
```

Outcome remains the existing audit dimension (`succeeded`, `denied`, `failed`).

The workspace event target includes:

```text
repository-registered
repository-status-changed
repository-evidence-changed
project-repository-bound
project-repository-binding-retired
```

Unchanged successful inspection writes immutable evidence and audit but no event or notifier.

## 11. Structural journal correlation

The A2b migration rebuilds `workspace_events` and adds:

```text
repository_id
repository_inspection_id
repository_binding_id
```

Rules:

- inspection correlation requires repository correlation;
- binding correlation requires project and repository correlation;
- composite foreign keys prove same workspace and same parent graph;
- the rebuild preserves row count, sequence values, append-only triggers, and existing event behavior;
- payload-only repository identity is not accepted.

## 12. Common non-goals

CT-04A2 does not implement:

- target refs, exact base revisions, or change requests;
- branch, checkout, worktree, status, diff, artifact store, or cleanup;
- agent, verification, review, remediation, readiness, or merge behavior;
- remote Git or credentials;
- repository rename;
- startup reconciliation or background polling;
- automated repair of corrupt stored evidence;
- mutation eligibility based solely on registration-time risk evidence;
- repository browser views beyond event-projection compatibility.

## 13. Parent exit gate

CT-04A2 is complete only after A2a and A2b are accepted and the composed implementation proves:

```text
Owner registers a quiescent ActionQueue repository through accepted A1.
Two complete inspections agree before the transaction.
The exact full observation is immutable and integrity-checked on read.
Repository state, audit, event, and notifier ordering are correct.
Environmental evidence can be reaffirmed without changing repository ID or bindings.
Structural identity replacement becomes terminal mismatch.
A repository may bind to several same-workspace projects; each project has one active binding.
Unbind affects one binding only.
Retirement closes all active bindings and releases the active identity reservation.
Cross-workspace and same-workspace/wrong-parent combinations fail structurally.
Repository event correlation survives snapshot-plus-cursor reconstruction.
No A2 code imports child_process or creates another host-inspection path.
The complete original CT-04A protected suite passes against A1+A2.
```
