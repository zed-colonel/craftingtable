# CT-04A2b2 — Authorized repository lifecycle and CT-04A parent fan-in

**Status:** Source-grounded parent contract; decomposed before implementation  
**Parent:** CT-04A2b  
**Depends on:** accepted CT-04A1, CT-04A2a, and CT-04A2b1  
**Source archive head:** `dd9c9699f0d86cae00fc1bf0d054224880c8dbed`  
**Risk:** Critical

## 1. Objective

Compose the accepted Git observation boundary, repository persistence model, and repository journal/projection model into authenticated, durable local repository lifecycle commands. Complete the original CT-04A parent contract without acquiring branch, worktree, diff, agent, verification, review, or merge authority.

## 2. Why the slice fans out again

The accepted source exposes three separate proof domains:

```text
Host/evidence boundary
    optional feature configuration
    one exact A1 adapter
    stored-evidence integrity
    observation classification

Repository identity lifecycle
    registration
    verification
    environmental reaffirmation
    query and administrative disclosure
    state + audit + event + notifier transactions

Administrative relationship lifecycle
    project binding and unbind
    repository retirement
    parent protected-suite fan-in
```

Each can be accepted before the next depends upon it. Combining all three would recreate the broad review surface that recursive decomposition exists to avoid.

## 3. Child sequence

| Child | Purpose | New authority | Completion dependency |
|---|---|---|---|
| `CT-04A2b2a` | Compose and validate the accepted A1 observation boundary | Read operator-approved repository state through one internal port | Required before any lifecycle command may call A1 |

## 5. Common invariants

### B2-I01 — One production Git adapter

Only the accepted A2b2a adapter may import `@craftingtable/git` in production server source. Lifecycle services consume an Exoskeleton-neutral internal observation port and never construct commands or parse raw Git output.

### B2-I02 — Optional does not mean implicit

With no repository configuration, the daemon starts and planning/authentication remain available. A partial or malformed repository configuration fails startup. The implementation never falls back to ambient current directory, implicit roots, or an unreviewed Git executable.

### B2-I03 — Authorization precedes host access

No unauthorized, nonmember, or insufficient-role request creates the inspector, inspects a path, verifies stored evidence through A1, or reveals feature configuration.

### B2-I04 — Exact stored evidence is verified before use

The daemon recomputes the SHA-256 of the exact stored observation string, parses it through A1, and compares every projected identity, environment, risk, version, and policy field. A mismatch becomes storage-integrity evidence and no host inspection occurs.

### B2-I05 — Repository class is not generic core mismatch

An A1 failure whose subject is `repository-class-changed` produces an explicit assessment and the durable reason `repository-class-changed`. It is not collapsed into a fingerprint mismatch or an operational failure.

### B2-I06 — Operational failures do not become identity judgments

`observation-raced`, timeouts, overflows, spawn faults, aborted requests, configuration unavailability, and malformed process output append bounded failed evidence where policy requires but do not automatically mutate repository identity state.

### B2-I07 — Explicit inspection is durable history

Every authorized explicit verification or reaffirmation attempt appends one immutable inspection record, including unchanged success, risk-only success, rejected reaffirmation, and bounded failure. The event journal is not an inspection history feed; history is queried explicitly.

### B2-I08 — Expansion of baseline is explicit

Only Owner reaffirmation of a still-same-core, still-environment-different observation may advance `acceptedEnvironmentInspectionId`. It preserves RepositoryId and project bindings.

### B2-I09 — State, audit, events, and evidence are atomic

For each authoritative command, repository/binding state, inspection evidence, audit, and accepted B1 workspace events commit in one outer transaction. Nested storage primitives are not final success until the outer commit succeeds.

### B2-I10 — Notification follows commit

The notifier is called once after commit only when one or more workspace events were appended. Unchanged successful inspection and failed/no-state-change evidence append no event and call no notifier.

### B2-I11 — Fresh verification precedes binding

Binding verifies stored evidence and performs a fresh A1 observation before the transaction. The transaction first applies the governed inspection result; it creates the binding only if the repository remains active at the expected version.

### B2-I12 — Retirement is host-independent

Retirement and explicit unbind do not call A1. They operate on accepted stored state, are idempotent, and emit complete structurally correlated events.

### B2-I13 — Read access does not imply administrative disclosure

Ordinary member responses exclude Git/common-directory paths and raw observation JSON. Owner-only administrative responses may expose approved canonical paths. No response exposes raw stderr, environment, config values, credentials, or another workspace's IDs.

### B2-I14 — Retired state is terminal

Retired repositories and bindings do not reactivate. A new registration uses a new RepositoryId after uniqueness is durably released.

### B2-I15 — Parent obligations survive decomposition

The complete original CT-04A and A2/A2b protected suites remain the final parent gate. A child-focused pass cannot mark CT-04A complete.

## 6. Shared authorization matrix

| Operation | Owner | Editor | Viewer |
|---|---:|---:|---:|
| Register host path | Yes | No | No |
| List/read common repository state | Yes | Yes | Yes |
| Read owner administrative identity | Yes | No | No |
| List bounded inspection history | Yes | Yes | Yes |
| Explicit inspect | Yes | Yes | No |
| Reaffirm environment baseline | Yes | No | No |
| Bind/unbind project | Yes | Yes | No |
| Retire repository | Yes | No | No |

Known members with insufficient role receive a bounded denied audit according to the command policy before host access. Nonmembers receive the existing indistinguishable 404 behavior and no cross-workspace disclosure.

```text

all original CT-04A, A2, and A2b protected cases pass;

```
