# CT-01 — Establish scope, repository contract, and executable skeleton

**Risk:** Medium  
**Dependencies:** None  
**Status:** Approved for implementation

## Objective

Create a small, executable TypeScript monorepo that establishes CraftingTable's architectural boundaries and visual language. The result must provide a running server, a running browser app, shared runtime-validated contracts, a fake agent backend, a fake Git service, and one normalized fake agent event visible in the UI.

This work item establishes the foundation. It must not implement later product features.

## Required reading

- `AGENTS.md`
- `CLAUDE.md`
- `docs/ui-principles.md`
- `init/craftingtable-implementation-plan.md`, especially Sections 0–3, 8, 11, 16 (`CT-01`), 17, 20, and 21
- `init/craftingtable-work-breakdown.yaml`
- `init/craftingtable-adapter-assumption-ledger.yaml`

## Required technical baseline

Use a deliberately simple TypeScript workspace:

- pnpm workspaces without Nx or Turborepo;
- Node.js on a maintained LTS release, pinned and documented;
- TypeScript strict mode;
- Fastify for the server;
- React and Vite for the browser;
- Zod for shared runtime contracts;
- Vitest for unit tests;
- Playwright for one browser smoke test;
- one formatter/linter approach chosen for simplicity and documented in ADR-001 or a companion tooling ADR.

Do not add a database in CT-01.

## Expected logical structure

The implementation should create, at minimum:

```text
apps/server
apps/web
packages/contracts
packages/domain
packages/agents
packages/git
packages/testing
scripts
fixtures
```

Physical consolidation is allowed only when dependency direction remains obvious.

## Domain seed

Define branded or otherwise non-interchangeable identifiers sufficient for the fake event path, including at least:

```text
UserId
WorkspaceId
ProjectId
WorkItemId
AgentRunId
EventId
```

Define a runtime-validated `AgentEventEnvelope` with:

```text
id
sequence
occurredAt
workspaceId
projectId, optional
workItemId, optional
runId, optional
kind
payload
```

Keep the initial event-kind vocabulary deliberately small. Include only what the fake dashboard needs.

## Server slice

Implement:

- `GET /api/health` returning a typed health response;
- `GET /api/events` as an SSE endpoint;
- a fake event source that emits at least one valid normalized event;
- clean startup and shutdown;
- shared contract validation at the boundary.

No authentication, SQLite, real agent process, arbitrary commands, or LAN/TLS deployment.

## Browser slice

Implement a desktop-first dashboard shell following `docs/ui-principles.md` that:

- connects to the SSE endpoint;
- renders connection state;
- displays one normalized fake agent event;
- visually suggests the future `Needs attention`, `Active`, `Ready`, and `Blocked` regions;
- clearly labels all current data as simulated;
- works after a normal page refresh;
- has a minimal error and disconnected state.

Do not implement routing-heavy application structure, a general component library, diff viewing, code editing, terminal emulation, or real project management.

## Fake boundaries

Define narrow interfaces for:

- an `AgentBackend` capable of describing itself and providing a fake event stream;
- a `GitService` sufficient to demonstrate dependency inversion without invoking real Git.

Place fake implementations in a test/development boundary. Do not design the complete future interfaces.

## Repository contracts

Create or complete:

- `README.md` scope charter;
- `CONTRIBUTING.md`;
- architecture boundary documentation;
- ADR-001 through ADR-007, deciding only what CT-01 needs and marking the rest deferred;
- local scripts for format, lint, type-check, unit tests, smoke test, and aggregate verification;
- a forbidden-scope check that fails if runtime dependencies on ActionQueue, WorldInterface, or Exoskeleton are introduced.

## Required commands

The root workspace must expose stable commands equivalent to:

```text
pnpm dev
pnpm build
pnpm format
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm test:e2e
pnpm check
```

`pnpm check` must be the CI-equivalent local quality gate.

## Acceptance criteria

All of the following must be true:

1. The server starts and responds successfully at `/api/health`.
2. The web app starts and loads without console errors.
3. Shared schemas compile and validate both the health response and fake event envelope.
4. The browser receives an SSE event from the fake backend and displays it.
5. The UI follows the committed visual principles and is usable at a typical MacBook viewport.
6. Unit tests cover the shared contracts and fake boundaries.
7. A Playwright smoke test proves the dashboard loads and the fake event appears.
8. Format, lint, type-check, build, unit-test, smoke-test, and forbidden-scope checks pass through `pnpm check` or clearly documented constituent commands.
9. No CT-02-or-later functionality is implemented.
10. The final report lists changed files, commands run, decisions made, deferred decisions, and unresolved risks.

## Explicit non-goals

Do not implement:

- authentication or users;
- SQLite or migrations;
- persistent audit events;
- plan import;
- repository registration;
- real Git commands or worktrees;
- real Codex, Claude Code, or OpenCode integration;
- verification runners beyond repository quality commands;
- diff viewing or inline review;
- merge operations;
- parallel agent runs;
- Planning Studio;
- LAN exposure or `systemd` deployment.

## Stop conditions

Stop and ask for direction before proceeding if:

- the installed environment cannot support the required baseline without a major alternative;
- a major framework not listed here seems necessary;
- acceptance requires implementing a non-goal;
- the work contract conflicts with the implementation plan;
- dependency installation or generated scaffolding would overwrite planning artifacts.
