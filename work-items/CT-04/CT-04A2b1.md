# CT-04A2b1 — Repository journal correlation and browser projection

**Parent:** CT-04A2b  
**Risk:** Critical  
**Dependencies:** accepted CT-04A2a at `e3b69c612a51b0b2a8d436ae3ea5355abd40745e`  
**Primary areas:** schema 4 journal rebuild, event vocabulary, strict contracts, storage mapping, browser invalidation and activity

## 1. Objective

Create the complete durable repository-event boundary before repository lifecycle services can emit events.

B1 is authority-free with respect to Git and repository commands. It adds no repository routes, no server service, no A1 adapter, and no notifier-producing lifecycle command.

## 2. Event vocabulary

B1 adds exactly five event kinds:

```text
repository-registered
repository-status-changed
repository-evidence-changed
project-repository-bound
project-repository-binding-retired
```

### 2.1 Correlation fields

`WorkspaceEventBase` and `workspace_events` add optional:

```text
repositoryId / repository_id
repositoryInspectionId / repository_inspection_id
repositoryBindingId / repository_binding_id
```

### 2.2 Event payloads

The accepted plan may refine field names but must preserve these semantics.

```ts
repository-registered {
  repositoryId;
  inspectionId;
  displayName;
  status: 'active';
  statusReason: 'registration-accepted';
  version: 1;
}

repository-status-changed {
  repositoryId;
  inspectionId?: RepositoryInspectionId; // absent only for operator retirement
  displayName;
  fromStatus;
  toStatus;
  statusReason;
  priorVersion;
  resultingVersion; // exactly prior + 1
}

repository-evidence-changed {
  repositoryId;
  inspectionId;
  displayName;
  evidenceClass: 'risk-scan';
  repositoryVersion; // unchanged repository state version
}

project-repository-bound {
  projectId;
  repositoryId;
  bindingId;
  repositoryDisplayName;
  bindingVersion: 1;
}

project-repository-binding-retired {
  projectId;
  repositoryId;
  bindingId;
  repositoryDisplayName;
  priorVersion;
  resultingVersion; // exactly prior + 1
}
```

Payloads expose no Git directory, raw observation, error evidence, command output, environment, or future readiness claim.

## 3. Schema 4

Migration `0004-ct04a2b-repository-journal.sql` must:

1. preserve migrations 0001–0003 byte-for-byte;
2. seed the five event kinds with `introduced_in_schema = 4`;
3. preserve the existing event-kind catalog immutability;
4. rebuild `workspace_events` with the three repository correlation columns;
5. preserve every old row, event ID, payload byte string, and sequence;
6. preserve or correctly restore `sqlite_sequence` so the next event sequence exceeds the prior maximum;
7. restore append-only update/delete triggers and indexes;
8. add structural FKs:

```text
(workspace_id, repository_id)
    → registered_repositories(workspace_id, id)

(workspace_id, repository_id, repository_inspection_id)
    → repository_inspections(workspace_id, repository_id, id)

(workspace_id, project_id, repository_id, repository_binding_id)
    → project_repository_bindings(workspace_id, project_id, repository_id, id)
```

9. enforce kind-specific correlation presence/absence, including:

```text
legacy kinds
    all repository correlation columns NULL

repository-registered
    repository + inspection required; project/binding/work-item absent

repository-status-changed
    repository required; inspection optional; project/binding/work-item absent

repository-evidence-changed
    repository + inspection required; project/binding/work-item absent

project-repository-bound / retired
    project + repository + binding required; inspection/work-item absent
```

10. run count, max-sequence, correlation, trigger, FK, and integrity guards before dropping the old table.

## 4. Storage boundary

Update the append input and row mapper so structural correlation is explicit. The mapper remains exhaustive over every event kind.

A new event kind without:

- a domain variant;
- a Zod schema;
- a storage mapping branch;
- a browser invalidation decision;
- an activity description;

must fail compilation or deterministic tests.

The storage API does not infer IDs from payload JSON. Callers supply structural correlation and strict payload separately.

## 5. Browser projection

Extend stale scopes with repository state:

```ts
repositoryList: boolean;
repositoryIds: readonly RepositoryId[];
```

Minimum invalidation:

| Event | Invalidation |
|---|---|
| repository-registered | repository list + repository ID |
| repository-status-changed | repository list + repository ID |
| repository-evidence-changed | repository list + repository ID |
| project-repository-bound | project ID + repository ID |
| project-repository-binding-retired | project ID + repository ID |

No repository page or fetch is added. CT-04E will consume these stale scopes. B1 only ensures durable event reconstruction, safe activity text, and future invalidation vocabulary.

## 6. B1 forbidden scope

B1 must not:

- import `@craftingtable/git`;
- import `node:child_process`;
- add repository feature configuration;
- create repository service or routes;
- call A1;
- write repository state, inspections, or bindings from a server command;
- add notifier behavior specific to repository commands;
- change A2a state primitives;
- implement registration, inspection, reaffirmation, retirement, binding, or unbind;
- add repository views;
- add CT-04B+ behavior.

## 7. B1 exit gate

```text
schema 3 migrates to schema 4 without journal loss or sequence drift
all new structural correlations reject wrong-workspace/wrong-parent rows
all five event shapes round-trip through storage and contracts
legacy event behavior remains unchanged
browser projection remains exhaustive and workspace-safe
activity rendering safely describes every kind
no A1/Git/service/route authority exists
all CT-01 through A2a tests pass
```
