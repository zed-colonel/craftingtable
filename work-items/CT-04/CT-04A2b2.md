# CT-04A2b2 — Authorized repository lifecycle and CT-04A parent fan-in

**Status:** Preliminary child contract; source-specific planning begins after A2b1 acceptance  
**Parent:** CT-04A2b  
**Depends on:** accepted CT-04A1, CT-04A2a, and CT-04A2b1  
**Risk:** Critical

## 1. Objective

Compose the accepted A1 observer, A2a repository model, and A2b1 journal/projection boundary into authenticated, durable repository lifecycle commands.

## 2. Required outcomes

- optional-but-strict repository feature configuration;
- one exact server adapter as the sole production `@craftingtable/git` consumer;
- A1/domain vocabulary and policy-version parity checks;
- authorization and expected-version checks before A1 creation/inspection;
- double-inspection quiescent registration;
- exact stored evidence digest/parse/projection verification;
- explicit repository-class-changed assessment support;
- governed verification, risk evidence, environmental change, core mismatch, unavailable, and storage-integrity behavior;
- Owner environmental reaffirmation;
- Owner repository retirement;
- Owner/Editor project binding and explicit unbind;
- strict list/detail/inspection/admin endpoints;
- bounded denied/failed/succeeded audit policy;
- atomic state + audit + accepted b1 event transactions;
- notifier only after commit;
- route inventory, CSRF/origin/session behavior, and non-disclosing errors;
- complete CT-04A parent protected fan-in.

## 3. Binding rules

- Missing repository configuration leaves planning/authentication available and host operations explicitly unavailable.
- Explicit malformed repository configuration fails startup.
- No unauthorized request may create or call the inspector.
- Registration stores one of two matching observations and attests both exact digests in audit metadata.
- Stored evidence integrity is checked before A1 parsing/comparison.
- Failed registration has no repository parent or inspection row; it may produce bounded request-workspace audit only.
- Every explicit verification/reaffirmation appends immutable inspection evidence.
- `observation-raced`, timeout, overflow, and host-process faults do not automatically change repository status.
- Repository-class errors enter terminal `identity-mismatch / repository-class-changed` through an explicit reducer variant.
- Unchanged success creates audit/evidence but no workspace event or notifier.
- Risk-only change creates evidence event without status/version change.
- Environmental change enters `identity-evidence-changed`.
- Owner reaffirmation preserves repository identity and bindings while advancing the baseline.
- Binding performs a fresh verification and either commits the governed state result or creates the binding; it never binds a newly non-active repository.
- Retirement does not call A1 and emits one binding-retired event per affected project.
- Retired rows never reactivate.
